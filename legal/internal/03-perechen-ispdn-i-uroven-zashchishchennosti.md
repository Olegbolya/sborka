# Перечень информационных систем ПД, категории данных, уровень защищённости, модель угроз

> **Внутренний документ оператора. Не публикуется.** Основание: ст. 19 152-ФЗ, ПП РФ № 1119, приказ ФСТЭК № 21. **Уровень защищённости подтверждает юрист или специалист по защите информации** — ниже расчёт, сделанный по открытым нормам.

## 1. Перечень ИСПДн

| № | Система | Где расположена | Какие ПД | Кто обрабатывает |
|---|---|---|---|---|
| 1 | «Блоккер»: API, база PostgreSQL `blokum_db`, Redis (БД 3), файловое хранилище медиа | Домашний сервер в РФ, `{{АДРЕС_РАЗМЕЩЕНИЯ_СЕРВЕРА}}`; конкретное размещение — вопрос №3 в `docs/05-LEGAL.md` §9 | Данные создателей (телефон, имя, идентификаторы VK ID / Яндекс ID, email), ответы участников, обращения, журналы | Оператор |

## 2. Категории ПД

Иные (не специальные, не биометрические, не общедоступные). Специальные и биометрические категории не обрабатываются. Количество субъектов — оценка владельца: {{ОЦЕНКА_ЧИСЛА_СУБЪЕКТОВ}} (ожидается менее 100 тысяч).

## 3. Тип актуальных угроз и уровень защищённости (ПП № 1119, п. 7–11)

- Тип угроз: **3-й** (угрозы, не связанные с недокументированными возможностями в системном и прикладном ПО), если используется только штатное ПО и нет подтверждённых угроз НДВ. Если юрист или специалист придёт к другому выводу — пересчитать.
- Категория ПД — иные; субъекты — не работники оператора; количество субъектов — менее 100 тысяч.
- По таблице п. 11 ПП № 1119 для иных ПД, типа угроз 3 и менее 100 тысяч субъектов (не сотрудников) получается **4-й уровень защищённости (УЗ-4)**. Для 100 тысяч и более — 3-й уровень. При включении ответов с ПД участников по поручению создателей число субъектов следить по базе раз в квартал.

## 4. Меры для УЗ-4 и как они выполнены

| Мера (ПП № 1119 п. 13 и приказ ФСТЭК № 21) | Как выполнена |
|---|---|
| Режим помещений, где размещены ИСПДн; сохранность носителей | Сервер в закрытом помещении, доступ — только владелец; носители с копиями шифруются |
| Доступ только лиц из перечня | Документ 05; вход на сервер по SSH-ключу, без пароля; роли в продукте: USER / MODERATOR / ADMIN |
| Использование средств защиты, прошедших оценку соответствия, если нужно | Для УЗ-4 при отсутствии актуальных угроз НДВ — не требуется; антивирус ClamAV для загрузок, обновления ОС |
| Назначение ответственного | Документ 02 |
| Учёт и аудит | Журнал аудита администраторов (хранится 3 года, неизменяем), журнал входов, журнал уничтожения |
| Шифрование и целостность | TLS при передаче, шифрование резервных копий, хэширование IP и токенов |
| Резервирование и восстановление | Ежедневные копии, ротация 30 дней, регулярная проверка восстановления (рабочий процесс «Проверка резервных копий») |
| Обнаружение и реакция на инциденты | Документ 06, оповещения администратору |
| Обновления | Регулярные обновления ОС и зависимостей, аудит зависимостей в CI |

**Владелец перед запуском подтверждает меры, которые относятся к самому серверу** (режим помещения, шифрование диска и копий, сетевые ограничения, регулярность обновлений): код их не проверяет, часть видна в «Диагностике сервера».

## 5. Модель угроз (кратко)

| Угроза | Источник | Мера |
|---|---|---|
| Подбор или перехват входа | Внешний нарушитель | Вход только через VK ID / Яндекс ID / телефон с кодом, ограничение частоты, капча, второй фактор для администраторов |
| Утечка из резервной копии | Внешний, внутренний | Шифрование копий, доступ по ключу, ротация |
| Захват сервера | Внешний | SSH только по ключу, сетевые ограничения, обновления, отдельные пользователи для процессов, отдельная БД и Redis-база |
| Вредоносные файлы в загрузках | Пользователь | Проверка по сигнатуре, ClamAV, перекодирование, запрет HTML/JS/SVG от пользователей |
| Раскрытие ответов участников посторонним | Создатель, внешний | Ответы видит только владелец сборки; ключ правильных ответов не уходит в браузер |
| Ошибка администратора | Внутренний | Журнал аудита; опасные действия требуют подтверждения |
| Физический доступ | Внутренний | Режим помещения, шифрование диска |
