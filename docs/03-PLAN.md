# 03 · План реализации «Блокума»

> Исполнитель — ИИ-агент (по умолчанию **Claude Sonnet, effort medium**). Задачи с пометкой **[OPUS]** (и все задачи фаз с пометкой в заголовке) рекомендуется выполнять на **Claude Opus, effort high** — в них архитектурные решения, движок сценариев, безопасность, деньги или юридические тексты. Каждую фазу после выполнения проверяет **отдельная сессия Opus high** по промпту `docs/prompts/REVIEW.md` — работа не оценивает сама себя.
>
> **Как читать задачу.** «Покрывает» — идентификаторы требований из `01-PRODUCT-SPEC.md`, `05-LEGAL.md`, `06-TRUST-SAFETY.md`: **каждый** из них должен быть реализован полностью. «Приёмка» — проверяемые условия: задача закрыта, только когда выполнены **все**. «Тесты» — какие тесты обязательно написать (не «какие-нибудь тесты»).
>
> **Главный принцип продукта** (`01-PRODUCT-SPEC.md`, вступление): инструменты вместо готовых решений. Нигде в коде нет «зашитых» игр, тем или шаблонов — только универсальные блоки, свойства, сценарии и поведения. Системные темы, шаблоны и библиотека — это **данные**, и продукт обязан работать, когда их нет.

## Общее определение готовности (DoD) — действует для КАЖДОЙ задачи

1. Выполнены **все** пункты «Приёмки» буквально. Частично выполненная задача — не выполнена.
2. Реализованы **все** требования из «Покрывает». Если требование оказалось невозможно реализовать как написано — задача получает статус ⛔ с причиной в `docs/PROGRESS.md`, а не «упрощённую версию».
3. Нет запрещённых шаблонов (`scripts/check-forbidden.mjs`): `TODO`, `FIXME`, «not implemented», пропущенные тесты, `@ts-ignore`, `eslint-disable` без причины, «рыба»-тексты, заглушки вместо реализации.
4. Написаны тесты из пункта «Тесты»; покрытие строк ≥ 80 % для `packages/schema`, `packages/engine` и доменных сервисов `apps/api` (порог задан в конфиге vitest, CI падает при снижении).
5. `pnpm verify` зелёный. Для задач с интерфейсом — e2e зелёные, скриншоты на ширине **390** и **1440** (для редактора ещё **1024**) **открыты и просмотрены** агентом (инструмент Read по PNG), замечания исправлены.
6. Коммиты с сообщением `тип(Pn.m): что сделано` (например `feat(P3.4): инспектор — тени и обводка`), push в `main`, CI зелёный.
7. `docs/PROGRESS.md`: статус ✅, хэш коммита, доказательство (какие команды запускались и их итог, имена ключевых тестов, пути к скриншотам).
8. Регрессий нет: полный набор тестов зелёный; после P6.8 и P6.9 — эталонные e2e `golden-ded-moroz` и `golden-own-game` зелёные.
9. Если задача меняет то, что работает на сервере, — деплой прошёл, `/api/health` и `/healthz` отвечают (проверено workflow `server-diagnostics`).
10. **Трассировка.** Для каждого идентификатора требования из «Покрывает» (вида `B-11`, `PL-06`, `TR-07`; диапазоны вида `S-01…S-20` раскрываются) в `docs/TRACEABILITY.md` есть строка `| ID | задача | файл кода | файл теста |`, файл теста существует и **содержит этот ID в названии теста** (например `test('PL-06: 51-й участник видит «Сборка закрыта»', …)`). Это проверяет `scripts/check-progress.mjs` — задачу без трассировки нельзя отметить ✅.
11. Если у задачи нет отдельного списка «Приёмка», приёмка = п. 10 для каждого ID из «Покрывает» + e2e или интеграционный тест, который показывает требование в работе так, как оно описано в спецификации (а не его упрощённый вариант).
