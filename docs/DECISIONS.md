# Журнал технических решений

> Формат: номер, дата, решение, почему, последствия. Новое решение, отменяющее старое, ссылается на него. Изменения проверок качества (`scripts/check-*.mjs`, `scripts/verify.mjs`, `.claude/`, `ci.yml`) записываются сюда **и** требуют разрешения владельца.

### ADR-001 · 2026-10-19 · Стек
Next.js (web, плеер, кабинет, редактор, админка) + NestJS (API) + BullMQ (worker) + PostgreSQL/Prisma + Redis, монорепо pnpm/Turborepo, TypeScript strict. **Почему:** тот же подход работает у BST на этом сервере; NestJS даёт агенту жёсткую структуру большого API. **Последствия:** три процесса PM2.

### ADR-002 · 2026-10-19 · DOM-рендер и артборд 390
Блоки рисуются DOM-элементами, координаты в единицах артборда шириной 390, масштаб — CSS-переменной, не `transform`. Один пакет `renderer` для редактора и плеера. **Почему:** чёткий текст, доступность, одинаковый вид в редакторе и плеере (урок BST с двумя рендерами). **Последствия:** формы сложнее прямоугольника — через `clip-path` + SVG-обводку.

### ADR-003 · 2026-10-19 · Только российские внешние сервисы
**Почему:** локализация ПД и отсутствие трансграничной передачи (`05-LEGAL.md` §2.3). **Последствия:** шрифты и библиотеки — локально; проверка `check-foreign-services`.

### ADR-004 · 2026-10-19 · Вход: VK ID, Яндекс ID, телефон
**Почему:** ст. 10 149-ФЗ в ред. 406-ФЗ; вход только по email — серая зона. **Последствия:** расходы на СМС → основной путь VK/Яндекс, длинные сеансы.

### ADR-005 · 2026-10-19 · Соседство с BST на одном сервере
Отдельные каталог, порты 3100/3110, база, пользователь БД, Redis БД 3, PM2-имена `blokum-*`, nginx-файл. **Почему:** сервер общий, BST не должен пострадать. **Последствия:** однократная подготовка сервера владельцем с sudo.

### ADR-006 · 2026-10-19 · Без отпечатков браузера
«Одна попытка с устройства» — по токену в localStorage. **Почему:** отпечаток — сбор данных об устройстве без необходимости и без согласия. **Последствия:** ограничение обходится очисткой хранилища — это приемлемо и указано в интерфейсе.

### ADR-007 · 2026-10-19 · Подсчёт результатов на сервере
Ключ правильных ответов, баллы, теги и исход колеса фортуны — только на сервере. **Почему:** честность тестов и защита от подмены. **Последствия:** запрос `check` при мгновенной обратной связи.

### ADR-008 · 2026-10-19 · Цены и лимиты в БД
**Почему:** владелец меняет тарифы без релиза. **Последствия:** `Entitlements` — единственная точка решений.

### ADR-009 · 2026-10-19 · Ворота против неполной работы
Хуки Claude Code (`SessionStart`, `Stop`), `scripts/check-*.mjs`, трассировка «требование → тест», независимое ревью каждой фазы моделью Opus. **Почему:** исполнитель — ИИ-агент; нужно автоматически ловить заглушки, пропущенные требования и ложные «готово». **Последствия:** ослабление этих проверок — только с разрешения владельца.

### ADR-010 · 2026-10-20 · Название «Блокум», домен blokum.ru
Утверждено владельцем. В интерфейсе — кириллицей (закон о русском языке), латиница — в домене. Репозиторий остаётся `Olegbolya/sborka` (рабочее имя), серверные имена — `blokum-*`, `blokum_db`, `~/blokum`. **Последствия:** при переименовании репозитория обновить ссылки в `CLAUDE.md`, `docs/prompts/*`, `docs/03-PLAN.md`.

### ADR-011 · 2026-10-20 · Универсальный движок сценариев вместо встроенных игр
По требованию владельца мини-игры придумывают пользователи. Вместо блоков-игр — правила «Когда → Если → Сделать» (TR/CN/AC), поведения (BH) и переменные (VR), исполняемые одним детерминированным движком `packages/engine/runtime`. Готовые игры — примеры-шаблоны RG-01…RG-10, собранные штатными средствами; их собираемость — приёмочный тест движка. **Почему:** свобода творчества, один код для всех механик, тестируемость. **Последствия:** результаты игр считаются на устройстве участника (RN-02, честно помечаются в кабинете); исход, влияющий на результат, — на сервере (RN-01).

### ADR-012 · 2026-10-20 · Свободные темы и шаблоны как данные
Темы, шаблоны, «Мои элементы» и библиотека — записи в БД, а не код. Системные — те же записи с `ownerId = null`, публикуются администратором. Стиль по умолчанию задаётся для каждого типа блока. Публикация сборки хранит снимок токенов темы. **Последствия:** продукт обязан работать при пустых системных коллекциях; наполнение библиотеки — задача владельца.

### ADR-013 · 2026-10-20 · Безопасность пользовательских форматов
Lottie — только через `dotlottie-web` (ThorVG, без выполнения выражений), шрифты — перекодирование в WOFF2 через HarfBuzz, SVG — только импорт контура. Открытие ссылок и копирование из сценариев — только по жесту участника. **Почему:** пользователи загружают любые файлы и собирают любую логику; нельзя дать им исполнять код или строить цепочки перенаправлений.

### ADR-014 · 2026-10-20 · Самозанятость
Владелец — плательщик НПД. Продление подписок поддерживает два режима (`AUTO` с согласием, если провайдер даёт автоплатежи самозанятым, и `LINK` — по ссылке); доход с 1 января считается в админке с тревогами у лимита 2,4 млн ₽. Приём платежей в пользу создателей при НПД не делается (агентская схема).

### ADR-015 · 2026-10-20 · Версии инструментов (P0.1)
Проверено `npm view` на 20.10.2026: Node 22 LTS, **pnpm 10.34.7** (pnpm 12 через corepack в среде агента не устанавливался), Turborepo 2.11.9, **TypeScript 6.0.3** (последняя 7.0.2, но `typescript-eslint` 8.72 поддерживает только `<6.1`), ESLint 10.13 + typescript-eslint 8.72 (правила с проверкой типов), Vitest 5.0.5 (Vite 8, преобразование через Oxc — JSX настраивается в `@blokum/config/vitest`), Next.js 16.4.2 + React 19.3.1, **NestJS 12.2 (ESM-пакеты)** — поэтому весь репозиторий на ESM (`"type": "module"`, `module: NodeNext`, импорты с `.js`), тесты Nest — через `unplugin-swc` (сохраняет метаданные декораторов), zod 4.6.7, **ioredis 5.11.1** (с ним совместим `ioredis-mock` для тестов; BullMQ 6 поддерживает ioredis ≥ 5), **Prisma 7.10.1** для P0.3 (тег `latest` у Prisma указывает на 8.0.0-rc — релиз-кандидаты не используем). `eslint-plugin-react` не подключён — не поддерживает ESLint 10; правила хуков — через `eslint-plugin-react-hooks` 7.1.1.
Пакеты собираются `tsc` в `dist/` (ESM + `.d.ts`), приложения зависят от собранных пакетов (`turbo` → `^build`).

### ADR-016 · 2026-10-20 · Drizzle ORM вместо Prisma (P0.3)
Prisma 7 при `init`/`migrate` скачивает движок схемы с `binaries.prisma.sh`, а сеть песочницы агента его не пропускает (403) — будущие сессии не смогли бы генерировать и применять миграции. **Решение:** Drizzle ORM + drizzle-kit (чистый JS, без бинарников), драйвер `pg`; миграции — SQL-файлы в `packages/db/migrations`, применяются `runMigrations()` (идемпотентно) при деплое. **Отличия от черновика §5:** итог по всем точкам доступа в `project_stats_daily` хранится с `access_point_id = ''` (вместо NULL в первичном ключе); у тарифа отдельная цена разовой покупки `price_once_rub`; колонки `legal_hold` у пользователей, сборок и медиа (под `LEGAL_HOLD` данные не удаляются); `refunded_at` у заказов; статус у журналов запросов; размеры файлов и хранилища — `bigint`; журнал аудита защищён триггерами от UPDATE/DELETE/TRUNCATE на уровне БД (AD-08); единица библиотеки ссылается ровно на один файл (CHECK). Секционирование `play_events` по месяцам — когда таблица превысит ~10 млн строк (индекс по времени уже есть). Тестовые данные (`seedDevData`) запрещены при `NODE_ENV=production`; тарифы (`seedPlans`) создаются только если их нет и не перезаписывают правки из админки.

### ADR-017 · 2026-10-20 · Раскладка на сервере и деплой релизами (P0.4, P0.5)
Вместо `dist.prev` (как в BST) — релизы: каждая выкладка собирается в новом каталоге `releases/<время>-<коммит>`, затем атомарно переключается ссылка `current`, процессы перезапускаются **по одному** с проверкой здоровья (API → `/api/v1/health`, сайт → `/healthz`, воркер → свежий heartbeat в Redis). Если проверка не прошла — ссылка возвращается на прежний релиз и процессы перезапускаются на нём (проверено локально: `SIMULATE_BROKEN_API=1` → откат за ~60 с). **Отличия от плана P0.4:** sudoers для `deploy` не нужен — nginx настраивает только `server-setup.sh`, который запускает владелец через `sudo`; деплой nginx не трогает. Данные — в `/srv/blokum`. PM2-демон общий с BST, команды — только `--only blokum-*`. Миграции выполняются до переключения и должны быть **только аддитивными** (новые таблицы и колонки); удаление/переименование — в два релиза, чтобы откат на прежний код не ломался. Пароль режима «до запуска» генерирует setup-скрипт и показывает один раз.

### ADR-018 · 2026-10-20 · Наблюдаемость (P0.6)
Новый пакет `@blokum/observability`, общий для api, web и worker: логгер pino (JSON, `service`, `version`, `requestId`), маскирование **каждой** записи и текста тревоги (телефоны, e-mail, номера карт по Луну, коды рядом со словом «код», токены в заголовках и адресах, длинные hex-строки, значения полей с «password/token/secret/cookie/otp…»), `AsyncLocalStorage` для id запроса (web `proxy.ts` → заголовок `x-request-id` → API → `runJobWithContext` в задачах воркера), класс `Alerts` с антидребезгом (ключ — не чаще раза в 10 минут) и счётчиком по окну (20 ошибок 5xx за минуту → одна тревога), каналы Telegram-бот администратора и почта (через интерфейс `Mailer`, провайдер выберет владелец), контроль диска > 80 % в воркере раз в 10 минут. Тексты тревог не содержат ПД (маскируются ещё раз перед отправкой), поэтому Telegram допустим. `/api/v1/health` всегда отвечает 200, пока процесс жив (для проверки деплоя), а состояние БД, Redis и диска — в `checks` и `status: degraded`. Ошибки API — единый формат `{ error: { code, message } }` на русском; при 5xx клиент видит только код запроса.
