# Журнал технических решений

> Формат: номер, дата, решение, почему, последствия. Новое решение, отменяющее старое, ссылается на него. Изменения проверок качества (`scripts/check-*.mjs`, `scripts/verify.mjs`, `.claude/`, `ci.yml`) записываются сюда **и** требуют разрешения владельца.

### ADR-001 · 2026-10-19 · Стек
Next.js (web, плеер, кабинет, редактор, админка) + NestJS (API) + BullMQ (worker) + PostgreSQL/Prisma + Redis, монорепо pnpm/Turborepo, TypeScript strict. **Почему:** тот же подход работает у BST на этом сервере; NestJS даёт агенту жёсткую структуру большого API. **Последствия:** три процесса PM2.

### ADR-002 · 2026-10-19 · DOM-рендер и артборд 390
Блоки рисуются DOM-элементами, координаты в единицах артборда шириной 390, масштаб — CSS-переменной, не `transform`. Один пакет `renderer` для редактора и плеера. **Почему:** чёткий текст, доступность, одинаковый вид в редакторе и плеере (урок BST с двумя рендерами). **Последствия:** формы сложнее прямоугольника — через `clip-path` + SVG-обводку.

### ADR-003 · 2026-10-19 · Только российские внешние сервисы
**Почему:** локализация ПД и отсутствие трансграничной передачи (`05-LEGAL.md` §2.3). **Последствия:** шрифты и библиотеки — локально; проверка `check-foreign-services`.

### ADR-004 · 2026-10-19 · Вход: VK ID, Яндекс ID, телефон
**Почему:** ст. 10 149-ФЗ в ред. 406-ФЗ; вход только по email — серая зона. **Последствия:** расходы на СМС → основной путь VK/Яндекс, длинные сеансы.

### ADR-005 · 2026-10-19 · Соседство с BST на одном сервере
Отдельные каталог, порты 3100/3110, база, пользователь БД, Redis БД 3, PM2-имена `blokum-*`, nginx-файл. **Почему:** сервер общий, BST не должен пострадать. **Последствия:** однократная подготовка сервера владельцем с sudo.

### ADR-006 · 2026-10-19 · Без отпечатков браузера
«Одна попытка с устройства» — по токену в localStorage. **Почему:** отпечаток — сбор данных об устройстве без необходимости и без согласия. **Последствия:** ограничение обходится очисткой хранилища — это приемлемо и указано в интерфейсе.

### ADR-007 · 2026-10-19 · Подсчёт результатов на сервере
Ключ правильных ответов, баллы, теги и исход колеса фортуны — только на сервере. **Почему:** честность тестов и защита от подмены. **Последствия:** запрос `check` при мгновенной обратной связи.

### ADR-008 · 2026-10-19 · Цены и лимиты в БД
**Почему:** владелец меняет тарифы без релиза. **Последствия:** `Entitlements` — единственная точка решений.

### ADR-009 · 2026-10-19 · Ворота против неполной работы
Хуки Claude Code (`SessionStart`, `Stop`), `scripts/check-*.mjs`, трассировка «требование → тест», независимое ревью каждой фазы моделью Opus. **Почему:** исполнитель — ИИ-агент; нужно автоматически ловить заглушки, пропущенные требования и ложные «готово». **Последствия:** ослабление этих проверок — только с разрешения владельца.

### ADR-010 · 2026-10-20 · Название «Блокум», домен blokum.ru
Утверждено владельцем. В интерфейсе — кириллицей (закон о русском языке), латиница — в домене. Репозиторий остаётся `Olegbolya/sborka` (рабочее имя), серверные имена — `blokum-*`, `blokum_db`, `~/blokum`. **Последствия:** при переименовании репозитория обновить ссылки в `CLAUDE.md`, `docs/prompts/*`, `docs/03-PLAN.md`.

### ADR-011 · 2026-10-20 · Универсальный движок сценариев вместо встроенных игр
По требованию владельца мини-игры придумывают пользователи. Вместо блоков-игр — правила «Когда → Если → Сделать» (TR/CN/AC), поведения (BH) и переменные (VR), исполняемые одним детерминированным движком `packages/engine/runtime`. Готовые игры — примеры-шаблоны RG-01…RG-10, собранные штатными средствами; их собираемость — приёмочный тест движка. **Почему:** свобода творчества, один код для всех механик, тестируемость. **Последствия:** результаты игр считаются на устройстве участника (RN-02, честно помечаются в кабинете); исход, влияющий на результат, — на сервере (RN-01).

### ADR-012 · 2026-10-20 · Свободные темы и шаблоны как данные
Темы, шаблоны, «Мои элементы» и библиотека — записи в БД, а не код. Системные — те же записи с `ownerId = null`, публикуются администратором. Стиль по умолчанию задаётся для каждого типа блока. Публикация сборки хранит снимок токенов темы. **Последствия:** продукт обязан работать при пустых системных коллекциях; наполнение библиотеки — задача владельца.

### ADR-013 · 2026-10-20 · Безопасность пользовательских форматов
Lottie — только через `dotlottie-web` (ThorVG, без выполнения выражений), шрифты — перекодирование в WOFF2 через HarfBuzz, SVG — только импорт контура. Открытие ссылок и копирование из сценариев — только по жесту участника. **Почему:** пользователи загружают любые файлы и собирают любую логику; нельзя дать им исполнять код или строить цепочки перенаправлений.

### ADR-014 · 2026-10-20 · Самозанятость
Владелец — плательщик НПД. Продление подписок поддерживает два режима (`AUTO` с согласием, если провайдер даёт автоплатежи самозанятым, и `LINK` — по ссылке); доход с 1 января считается в админке с тревогами у лимита 2,4 млн ₽. Приём платежей в пользу создателей при НПД не делается (агентская схема).

### ADR-015 · 2026-10-20 · Версии инструментов (P0.1)
Проверено `npm view` на 20.10.2026: Node 22 LTS, **pnpm 10.34.7** (pnpm 12 через corepack в среде агента не устанавливался), Turborepo 2.11.9, **TypeScript 6.0.3** (последняя 7.0.2, но `typescript-eslint` 8.72 поддерживает только `<6.1`), ESLint 10.13 + typescript-eslint 8.72 (правила с проверкой типов), Vitest 5.0.5 (Vite 8, преобразование через Oxc — JSX настраивается в `@blokum/config/vitest`), Next.js 16.4.2 + React 19.3.1, **NestJS 12.2 (ESM-пакеты)** — поэтому весь репозиторий на ESM (`"type": "module"`, `module: NodeNext`, импорты с `.js`), тесты Nest — через `unplugin-swc` (сохраняет метаданные декораторов), zod 4.6.7, **ioredis 5.11.1** (с ним совместим `ioredis-mock` для тестов; BullMQ 6 поддерживает ioredis ≥ 5), **Prisma 7.10.1** для P0.3 (тег `latest` у Prisma указывает на 8.0.0-rc — релиз-кандидаты не используем). `eslint-plugin-react` не подключён — не поддерживает ESLint 10; правила хуков — через `eslint-plugin-react-hooks` 7.1.1.
Пакеты собираются `tsc` в `dist/` (ESM + `.d.ts`), приложения зависят от собранных пакетов (`turbo` → `^build`).

### ADR-016 · 2026-10-20 · Drizzle ORM вместо Prisma (P0.3)
Prisma 7 при `init`/`migrate` скачивает движок схемы с `binaries.prisma.sh`, а сеть песочницы агента его не пропускает (403) — будущие сессии не смогли бы генерировать и применять миграции. **Решение:** Drizzle ORM + drizzle-kit (чистый JS, без бинарников), драйвер `pg`; миграции — SQL-файлы в `packages/db/migrations`, применяются `runMigrations()` (идемпотентно) при деплое. **Отличия от черновика §5:** итог по всем точкам доступа в `project_stats_daily` хранится с `access_point_id = ''` (вместо NULL в первичном ключе); у тарифа отдельная цена разовой покупки `price_once_rub`; колонки `legal_hold` у пользователей, сборок и медиа (под `LEGAL_HOLD` данные не удаляются); `refunded_at` у заказов; статус у журналов запросов; размеры файлов и хранилища — `bigint`; журнал аудита защищён триггерами от UPDATE/DELETE/TRUNCATE на уровне БД (AD-08); единица библиотеки ссылается ровно на один файл (CHECK). Секционирование `play_events` по месяцам — когда таблица превысит ~10 млн строк (индекс по времени уже есть). Тестовые данные (`seedDevData`) запрещены при `NODE_ENV=production`; тарифы (`seedPlans`) создаются только если их нет и не перезаписывают правки из админки.

### ADR-017 · 2026-10-20 · Раскладка на сервере и деплой релизами (P0.4, P0.5)
Вместо `dist.prev` (как в BST) — релизы: каждая выкладка собирается в новом каталоге `releases/<время>-<коммит>`, затем атомарно переключается ссылка `current`, процессы перезапускаются **по одному** с проверкой здоровья (API → `/api/v1/health`, сайт → `/healthz`, воркер → свежий heartbeat в Redis). Если проверка не прошла — ссылка возвращается на прежний релиз и процессы перезапускаются на нём (проверено локально: `SIMULATE_BROKEN_API=1` → откат за ~60 с). **Отличия от плана P0.4:** sudoers для `deploy` не нужен — nginx настраивает только `server-setup.sh`, который запускает владелец через `sudo`; деплой nginx не трогает. Данные — в `/srv/blokum`. PM2-демон общий с BST, команды — только `--only blokum-*`. Миграции выполняются до переключения и должны быть **только аддитивными** (новые таблицы и колонки); удаление/переименование — в два релиза, чтобы откат на прежний код не ломался. Пароль режима «до запуска» генерирует setup-скрипт и показывает один раз.

### ADR-018 · 2026-10-20 · Наблюдаемость (P0.6)
Новый пакет `@blokum/observability`, общий для api, web и worker: логгер pino (JSON, `service`, `version`, `requestId`), маскирование **каждой** записи и текста тревоги (телефоны, e-mail, номера карт по Луну, коды рядом со словом «код», токены в заголовках и адресах, длинные hex-строки, значения полей с «password/token/secret/cookie/otp…»), `AsyncLocalStorage` для id запроса (web `proxy.ts` → заголовок `x-request-id` → API → `runJobWithContext` в задачах воркера), класс `Alerts` с антидребезгом (ключ — не чаще раза в 10 минут) и счётчиком по окну (20 ошибок 5xx за минуту → одна тревога), каналы Telegram-бот администратора и почта (через интерфейс `Mailer`, провайдер выберет владелец), контроль диска > 80 % в воркере раз в 10 минут. Тексты тревог не содержат ПД (маскируются ещё раз перед отправкой), поэтому Telegram допустим. `/api/v1/health` всегда отвечает 200, пока процесс жив (для проверки деплоя), а состояние БД, Redis и диска — в `checks` и `status: degraded`. Ошибки API — единый формат `{ error: { code, message } }` на русском; при 5xx клиент видит только код запроса.

### ADR-019 · 2026-10-21 · Правила движка прохождения (P1.2)
`packages/engine/src/flow` — чистые функции над документом и состоянием-данными (`FlowState` хранится в сеансе). Принятые правила, которых нет в спецификации дословно:
- **Порядок «Дальше»:** сначала обязательные вопросы (только видимые: скрытые до события, скрытые условием и вложенные в скрытый контейнер не требуются), затем ветки экрана по порядку — первая выполненная решает, иначе следующий экран. Экраны, на которые ведут правила результатов, при обычном «дальше» пропускаются; после последнего — подсчёт результата.
- **Результат:** правила результатов проверяются в порядке, заданном создателем; первое подходящее побеждает (диапазон баллов включает границы; «личностный» — тег, выбранный чаще всех, ничья по `tieBreak`; «случайно» — из серверного источника). Переход на экран вида «результат» по ветке сразу завершает прохождение с результатом этого экрана (L-04 «по ветке»). Нет подходящего правила — системный экран конца.
- **Обратная связь «сразу»:** после ответа на вопрос с ключом участник видит вердикт, а ответ блокируется (`ANSWER_LOCKED`), иначе ключ можно подобрать перебором.
- **Согласие (B-20)** обязательно только тогда, когда на экране введены персональные данные (контакты или поле с пометкой имя/телефон/почта/город): без ПД согласие не нужно, принуждать к нему нельзя.
- **«НЕ» над несколькими условиями** — «ни одно не выполнено». Строки сравниваются без учёта регистра и пробелов по краям, «ё» и «е» различаются.
- **Таймер экрана:** сервер принимает «время вышло» не раньше чем за 1 с до конца (расхождение часов); при возврате на экран отсчёт начинается заново.
- **Случайность:** `RandomSource` — для всего, что влияет на результат (CN-05 с флагом, ничья), реализуется сервером; косметическая — `Rng` из seed.
- **Ключи ответов** — только у вопросов с вариантами (B-11, B-12). Для текстовых ответов, ранжирования и шкал ключа нет; правильность по ним можно задать сценарием (условие «ответ равен / содержит» → изменить переменную).
- **Подстановки в тексте:** кроме переменных (`{v}`) появились `{sys}` — «баллы», «максимум», «результат», «правильных», «вопросов» и системные переменные — и `{answer}` — ответ на вопрос (L-04, L-05). Валидатор проверяет ссылки текста на переменные и вопросы. Ветки и условия по ответам на вопросы с **прошлых** экранов больше не считаются ошибкой «блок с другого экрана» — так устроено ветвление L-02.

### ADR-020 · 2026-10-21 · Устройство движка сценариев (P1.3)
`packages/engine/src/runtime` — класс `Runtime` (`createRuntime(doc, { seed, randomSource, startedAt })`), без React, DOM и собственных таймеров: игрок передаёт события (`dispatch`), время (`tick(dt)`), рисует `views()` и выполняет возвращённые эффекты (`navigate`, `finish`, `effect`, `mediaOverlay`, `media`, `playSound`, `record`, `openLink`, `copyText`, `answer`, `warning`). Принятые правила:
- **Экземпляры блоков:** оригиналы и копии (`<образец>~<номер>`, копия контейнера копирует вложенные блоки). Копии создаются видимыми на верхнем уровне в координатах экрана, даже если образец скрыт: обычный приём — скрытый образец. «Любая копия X» (`copiesOf`) — только копии, без образца.
- **Правила:** сборки — на всех экранах, экрана и блоков — только на своём экране. Выполняются по приоритету (больше — раньше), при равном — в порядке документа. Счётчик срабатываний (CN-04) считает срабатывания триггера, включая текущее («на 5-й раз» = «равно 5»). Он и флаг «один раз» живут всё прохождение.
- **Интерпретатор** с явным стеком кадров: «Подождать» (AC-11) откладывает остаток цепочки, в том числе внутри «Повторить». Уход с экрана отменяет отложенное. «Перейти» и «Завершить» прекращают цепочку и все события до показа следующего экрана; «уход с экрана» (TR-09) при этом всё равно срабатывает, а переходы из него игнорируются.
- **SC-04:** каждое действие — шаг; больше 1000 шагов за секунду времени прохождения или больше 20 вложенных вызовов правил (через «переменная изменилась», «ответ») — правило останавливается до следующего показа экрана, эффект `warning` «Похоже на бесконечный цикл: правило «…» остановлено (…)». Счётчики для отладчика — `stats`.
- **TS-07:** ссылка и копирование выполняются только в цепочке, начатой жестом (нажатие, двойное, долгое, наведение, перетаскивание, отпускание, свайп, клавиша), и только **до** первой паузы: после «Подождать» браузер всё равно не даст открыть окно, а цепочка «жест → пауза → ссылка» выглядела бы как автоматический переход. Правила, вызванные изменением переменной, — не жест. Ссылка проверяется `SafeHref`.
- **AC-02:** значения проверяются схемой стиля (`BlockStyle.shape[…]`, `RichText`, `MediaRef`), неверные не применяются и дают `warning`. Плавно меняются числовые свойства рамки и анимируемые (`ANIMATABLE`), остальные — сразу. Новый набор эффектов/фильтров/3D сбрасывает их анимированные значения.
- **AC-04:** «случайное» для списка перемешивает его; «случайный элемент списка» берёт список из переменной, id которой указан в значении. Текст до 1000 символов, список до 500 элементов, деление на ноль не меняет значение.
- **CN-02 в браузере:** ключа ответов там нет (PL-15), поэтому «верно / неверно / баллы» работают по вердикту сервера (`setVerdict`); без вердикта — ложь.
- **TR-03:** игрок шлёт `longPress` один раз за удержание (при отпускании или на 3-й секунде), срабатывают правила с порогом ≤ длительности.
- **TR-07:** столкновение — пересечение прямоугольников в координатах экрана (без учёта поворота), через пространственную сетку 64×64 по целям каждого правила; блок не сталкивается со своими вложенными. Замер SC-05: 200 движущихся копий и 3 правила пересечений — 0,48 мс на `tick` в Node (`packages/engine/test/runtime.bench.ts`, отдельный шаг `verify` — см. ADR-021).
- **Движение для поведений** (BH-04/05, P1.9) — `setMotion(id, { vx, vy, ay })`: скорость в единицах артборда в секунду и ускорение.

### ADR-021 · 2026-10-21 · Рендерер, правило темы и язык ошибок (P1.4)
- **Стиль блока — частичное переопределение (TH-06).** `block.style` хранит только группы стиля, изменённые вручную (`StyleOverride` без значений по умолчанию; `BlockStyle.partial()` из zod 4 заполнял бы их и «своё» нельзя было бы отличить от «из темы»). Итоговый стиль — `resolveBlockStyle`: базовые значения ← стиль темы для типа блока ← свои группы ← состояние (S-15). Группа сливается целиком: редактор при правке любого поля пишет всю группу, и она становится своей. «Сбросить к теме» — `resetToTheme` удаляет группы. Цвета токенами (`{ token }`) перекрашиваются темой и внутри своих групп, HEX — нет. Движок сценариев тоже анимирует от итогового стиля.
- **Единица артборда без JS:** в плеере `--u: calc(min(100vw, 480px) / 390)`, в редакторе и миниатюрах `--u` задаётся в px; все размеры — `calc(n * var(--u))` (E-02), `transform: scale` на артборде нет.
- **Устройство блока в DOM:** `.bk-block` (позиция, размер, поворот, отражение, масштаб из сценария, прозрачность, фильтры, наложение) → `.bk-surface` (скругление, тени, свечение, размытие фона, слои заливки снизу вверх: `fills[0]` — нижний) и `.bk-content` (отступы, выравнивание текста или автораскладка, обрезка по форме, содержимое типа, текстовый слой, вложенные блоки). Вложенные блоки позиционируются от левого верхнего угла родителя. Заливка-плитка — клетки по 100 единиц × масштаб; масштаб заливки-картинки — `transform` слоя. Текст по дуге/кругу — SVG `textPath` с размером шрифта в единицах.
- **Контуры фигур, обводка по контуру и маски** добавляются в P1.6 (их задача — S-02, S-03, S-05, S-18, S-19); до неё блоки рисуются прямоугольниками со скруглением.
- **Адаптер движка** `RuntimeStore`: один `tick` за кадр `requestAnimationFrame` (шаг не больше 100 мс), изменения событий и кадров применяются пачкой, React перерисовывается только при изменениях (`useSyncExternalStore`). Нажатие, двойное нажатие и наведение мышью передаются в движок уже в P1.4; перетаскивание, свайп и долгое нажатие — в P1.9.
- **Проверка границы рендера** `scripts/check-render-boundary.mjs` (требование приёмки P1.4 в плане, утверждённом владельцем): в `apps/web` запрещены внутренние классы рендера, свои компоненты блоков/экранов, перевод стиля блока в CSS и импорт внутренностей рендера. Скрипт при каждом запуске проверяет себя на примерах. Добавлен шагом в `verify.mjs` — проверка только ужесточается.
- **Ошибки проверки данных по-русски без английских слов (N-05):** стандартная русская локаль zod печатает «array», «string» и значения перечислений, поэтому сообщения написаны в `packages/schema/src/locale.ts` («Слишком много элементов: не больше 4», «Недопустимое значение», «Лишнее поле в данных»).
- **Служебные темы** `DEV_THEMES.light/dark` — только для разработки и тестов, только системные шрифты; системные темы для пользователей наполняет владелец (TH-05).
- **Бенчмарк SC-05 — отдельным шагом `verify`.** Внутри общего прогона тестов (turbo запускает пакеты параллельно, движок — с инструментированием покрытия) замер показывал 2,3–4,7 мс вместо 0,4 мс: мерилась нагрузка соседних процессов. Бенчмарк перенесён в `packages/engine/test/runtime.bench.ts` (`pnpm --filter @blokum/engine bench`, без покрытия, файлы последовательно) и запускается в `verify.mjs` после параллельного прогона. Порог 2 мс не изменён, берётся лучший из 10 замеров по 30 тиков. Проверка не ослаблена: она по-прежнему обязательна и в CI.

### ADR-022 · 2026-10-21 · Формы, обводка и маски по контуру (P1.6)
- **Порядок задач:** P1.6 выполнена раньше P1.5 — матрица «свойство × тип блока» (P1.5) проверяет и форму, обводку, маску, которые появляются только в P1.6.
- **Произвольный контур** (`packages/schema/src/path.ts`): разбор только команд M L H V C S Q T A Z и чисел (отказ на любые другие символы, `url(`, сущности, числа больше 10⁶, больше 20 000 символов или 4 000 отрезков), перевод в абсолютные M/L/C/Z — дуги и квадратичные кривые становятся кубическими, поэтому растяжение контура на блок точное. `normalizePath` вписывает контур в 0…100; схема фигуры проверяет, что контур разбирается.
- **Контуры фигур** (`packages/renderer/src/shape/outline.ts`) строятся в единицах блока для его текущего размера. Многоугольник и звезда растягиваются на весь блок; скругление вершин — квадратичная кривая на доле `cornerRadius` от меньшего соседнего ребра. Клякса — сглаженная кривая через точки из `createRng(seed)`, вписанная по самой кривой. Облачко: тело уступает 20 % блока стороне хвостика, хвостик идёт к точке (точка внутри тела уводится к краю блока). Волна и зигзаг только по выбранным краям, внутрь блока.
- **Отрисовка:** прямоугольник, капсула и эллипс — CSS `border-radius` (тени остаются `box-shadow`). Остальные формы — `mask-image` с SVG контура на подложке и содержимом (если включена «обрезка по форме»); тени, свечение и внутренние тени таких форм — SVG-слои по контуру: растяжение через `feMorphology`, размытие `feGaussianBlur` (σ = размытие / 2), внешняя тень вырезана под блоком (на полединицы меньше контура — без шва сглаживания). Пустой SVG-фильтр делает элемент прозрачным, поэтому без размытия и растяжения фильтр не подключается.
- **Обводка у любой формы** — слой вокруг блока (на ширину обводки для «снаружи», на половину — «по центру»), закрашенный краской обводки (цвет или любой градиент, включая конический) и вырезанный маской-кольцом из SVG: «внутри» — линия двойной толщины, обрезанная контуром, «снаружи» — двойной толщины без внутренней части. Пунктир по умолчанию 3:2 толщины, точки — круглые концы с шагом 2 толщины, свой шаблон — в единицах.
- **Маски блока:** картинка по альфа-каналу (`contain`, по центру) и затухание краёв градиентами пересекаются (`mask-composite: intersect`). Маска действует на весь блок, включая тени.
- **Наклон за курсором (S-18):** в плеере блок пишет `--bk-tilt-x/y` прямо в стиль элемента (без перерисовки React), поворот — `calc((база + var(--bk-tilt-x, 0)) * 1deg)`, сила — `tiltStrength` градусов, при уходе указателя возврат в 0; у такого блока в плеере `touch-action: none` — палец наклоняет блок, а не прокручивает страницу.
- **Служебные картинки галерей** `/dev/*` рисует `scripts/dev/generate-dev-media.py` (зимний «снимок», GIF снегопада, маска-звезда) — без картинок из интернета; это не библиотека и не ассеты тем.

### ADR-023 · 2026-10-21 · Анимации, переходы, частицы и звуки (P1.7)
- **Motion 14.2.0** (MIT) — версия недельной давности (свежий выпуск вышел за два дня до начала задачи). API сверен по исходникам в `node_modules`. Motion получает только числа: планы анимаций — чистые данные (`packages/renderer/src/animation/plan.ts`, тестируются без DOM). Анимируются CSS-переменные слоя `.bk-anim` (`--bk-ax`, `--bk-as`, `--bk-ahue`…), а слой сам собирает из них `transform` и `filter` в единицах артборда. Поэтому анимация масштабируется вместе с артбордом, а свой поворот, отражения и 3D блока остаются на внешнем элементе.
- **Свои ключевые кадры** — любые свойства из `ANIMATABLE` плюс цвет заливки (`Keyframe.fill`), который накладывается слоем-тонировкой поверх заливок блока (S-04).
- **Переходы экранов** (`ScreenStage`): уходящий и приходящий экраны анимируются вместе, потом старый удаляется. Приходящий слой с первого кадра стоит в начальной точке, чтобы новый экран не мелькнул до старта Motion. Переход ветки или действия AC-05 важнее перехода экрана (T-30). Пресет ищется в теме (T-32). Медиа-переход и вставка по ответу (T-20, T-21) показываются до нового экрана, а после них экран появляется без второй анимации: мем и есть переход. Вердикт «правильно/неправильно» приходит с сервера (PL-15). Для проверок у приходящего слоя есть `data-transition`.
- **«Уменьшить движение» (T-31):** любой переход становится проявлением на 200 мс. Частицы и тряска не показываются, вспышка короче.
- **Состояния (S-15) в плеере:** наведение берётся от курсора (у пальца наведения нет), нажатие — от указателя. «Недоступно» включается, когда сценарий запретил взаимодействие (AC-18). «Выбрано», «перетаскивается» и «над зоной» приходят от движка. Отслеживаются только состояния, которые у блока заданы. Смена состояния плавная, 160 мс по прозрачности, фильтрам, цвету, скруглению и теням; `transform` не входит, потому что его ведёт движок по кадрам.
- **Частицы:**
  - Плотность считается на площадь: полный экран телефона (390 × 844) при плотности 1 вмещает 200 частиц, окно меньше — пропорционально меньше, но не меньше одной. Раньше любое окно получало те же 200 × плотность: галерея из 8 окон давала 1 120 частиц и 14–16 кадров/с на телефоне при CPU ×4.
  - Каждая форма и цвет рисуются один раз в спрайт, дальше частица — это `setTransform` и `drawImage`.
  - Плотность пикселей холста — не больше 1,5×.
  - Холст вне экрана не считает и не рисует (IntersectionObserver).
  - Итог при CPU ×4: 8 окон — 56–59 кадров/с, полный экран при плотности 100 % — 45–53 кадров/с (e2e `animations.spec.ts`, параллельный прогон).
- **Звуки** (`SoundManager`) молчат до первого нажатия или клавиши участника (правило браузеров), фон темы запускается после разблокировки. Участник может выключить звук, а включён ли он по умолчанию, решает создатель (`soundEnabledByDefault`).
- **Значок сайта** `app/icon.svg` (свой рисунок из блоков): без него каждая страница получала 404 на `/favicon.ico`, и e2e галереи ловит любые ответы ≥ 400.

### ADR-024 · 2026-10-21 · Матрица «свойство × тип блока» (P1.5)
- **Матрица** `packages/renderer/test/style-matrix.test.tsx`: 20 свойств S-01…S-20 × 22 типа × 2 служебные темы = 880 пар. Для каждой пары свойство задаётся блоку этого типа, и проверяется, что DOM изменился ожидаемо по сравнению с тем же блоком без свойства (тема по умолчанию для типа может задавать свои группы — например, скругление и тень у кнопки). Сам тест сверяет: список проверенных свойств равен S-01…S-20; список типов равен ключам `BLOCK_PROPS`; каждая группа `BlockStyle` и каждое поле блока относится к какому-то свойству (кроме id, типа, содержимого типа, вложенных блоков, поведений и правил). Проверка на прочность: если убрать из `styleToCss` один фильтр или отступы, падают ровно 44 пары соответствующего свойства.
- **S-11 у любого блока.** В спецификации медиа-настройки описаны «для блоков с медиа», а S-00 требует каждое свойство на каждом типе. Решение: у блока без своего медиа его медиа — это видеозаливка, поэтому автозапуск, звук, повтор, элементы управления, обложка и скорость блока применяются к его видеозаливкам. Раньше видеозаливка всегда шла со звуком выключенным и по кругу. Кадрирование и фокус-точка задаются у самой медиазаливки (S-04).
- **Сетка для глаз** `/dev/matrix`: 22 типа × 6 ключевых свойств (форма, градиент, обводка, тень со свечением, 3D, маска с фильтром). Строится на сервере (у вложенных блоков вопросов случайные id) и делится на экраны по 4 типа, потому что на экране не больше 100 блоков. e2e проверяет на каждом типе маску-звезду, обводку, наклон и затухание; скриншоты 390 и 1440 в обеих темах.

### ADR-025 · 2026-10-21 · Блоки (P1.8)
- **Содержимое блоков** — `packages/renderer/src/blocks/*`: медиа (B-02…B-05, B-07), вопросы (B-13…B-17, B-19, B-20) и отображение (B-08, B-09, B-22, B-23). `blockContent` по типу; у текста, фигуры, кнопки, контейнера и вопросов с вариантами своего содержимого нет — это текстовый слой и вложенные блоки. Редактор может подменить содержимое через `renderContent`.
- **Варианты ответа B-11/B-12** — самостоятельные вложенные блоки. `BlockView` даёт им роль `radio`/`checkbox`, `aria-checked`, табуляцию, нажатие и пробел; сам вопрос — `radiogroup`/`group` с именем. Выбор уходит в движок событием `answer`; «выбран» берётся из движка, а без движка — из ответов в контексте.
- **Логика в движке, а не в рендере:** «перейти сразу после выбора» (B-11) и «дальше после окончания видео» (B-04) выдают эффект `navigate: branch`. «Перемешивать» меняет местами варианты при входе на экран по зерну (косметическая случайность — после перезагрузки тот же порядок). `Runtime.currentAnswers` отдаёт ответы рендеру.
- **Таймер B-08:** движок считает в миллисекундах, блок показывает секунды (`PlayerScreen` переводит). Ошибку «1435:34» нашёл скриншот галереи; на неё есть тест на настоящем движке.
- **Дата B-17 — своё поле с русской маской** «дд.мм.гггг» / «чч:мм» / «дд.мм.гггг чч:мм» (`inputMode="numeric"`, проверка существования даты), ответ в ISO. Системное поле даты рисует формат на языке браузера («mm/dd/yyyy»), а английского в интерфейсе быть не должно. Кнопка «Календарь» открывает системный выбор через скрытое поле (`showPicker`).
- **Текст и контакты** уходят в движок после паузы 400 мс или при уходе из поля, а не на каждую букву, иначе правила «ответ изменён» (TR-12) срабатывали бы на каждый символ.
- **Lottie (B-07)** — только `@lottiefiles/dotlottie-web` 0.81.0 (MIT). Его wasm библиотека по умолчанию грузит с jsdelivr/unpkg, поэтому `apps/web/scripts/copy-vendor.mjs` кладёт его в `public/vendor/dotlottie-player-<версия>.wasm` перед `next build`/`next dev`, а рендер вызывает `setWasmUrl` до первой анимации. Если установленная версия не совпадает с `LOTTIE_WASM_URL`, сборка падает. e2e проверяет, что галерея не делает ни одного запроса за пределы сайта.
- **Доступность (PL-21):**
  - Любой блок с правилом на нажатие (и кнопка) — `role="button"`, табуляция, Enter и пробел. Кнопка «требует ответов» — `aria-disabled` и состояние «недоступно», пока на экране есть обязательные вопросы без ответа (та же проверка L-07, что в движке прохождения).
  - Alt медиа — у самого `<img>`/`<video>`; блок с подписью без своей роли — именованная `group`, потому что ARIA запрещает имя у элемента без роли.
  - Фокус с клавиатуры виден: кольцо в цвете темы, стиль только внутри артборда.
  - axe-core 4.13 по тегам WCAG 2.0/2.1 A и AA на `/dev/render-gallery`: 32 правила, 1 241 узел, 0 нарушений любой тяжести в обеих темах. На ручную проверку axe отдаёт контраст текста поверх градиентов и фото (его смотрим по скриншотам) и субтитры видео (их добавляет создатель).
- **Обводка — рамка поверх содержимого:** раньше фото и видео закрывали обводку, а с ней состояния «выбрано», «правильно», «над зоной» (нашлось в сетке состояний галереи).
- **Сетка состояний** галереи помечена `inert`: это картинка, её копии блоков не попадают в табуляцию и к скринридеру.
- **Служебные медиа галерей** — видео со снегопадом и обложкой (ffmpeg), звон бубенцов (WAV) и прыгающий снежок (Lottie JSON) рисует `scripts/dev/generate-dev-media.py`, без файлов из интернета.

### ADR-026 · 2026-10-21 · Поведения (P1.9)
- **Всё состояние поведений — в движке** (`packages/engine/src/runtime`), геометрия — чистые функции в `behaviors.ts`. Рендер только сообщает жесты и рисует.
- **BH-01 перетаскивание:**
  - Ось и границы применяет движок к каждому `dragMove`.
  - При отпускании блок притягивается только к своим зонам (если список пуст — любая зона засчитывается, но не притягивает). «Одна копия на зоне» считает занятую зону промахом. Промах с «вернуть на место» — плавный возврат в точку начала.
  - Движок принимает перетаскивание любого блока (старые сценарии P1.3 так проверялись), а плеер начинает его только у блоков с BH-01.
  - Указатель захватывается (`setPointerCapture`), у каждого блока свой палец — несколько блоков тянутся одновременно. Сдвиг больше 3 единиц — уже перетаскивание, и следующий за ним щелчок не считается нажатием.
- **BH-02 и BH-08** получают новое событие движка `pointer` (позиция пальца или курсора на экране в единицах). Экран отслеживает указатель, только если на нём есть такие блоки; палец сообщает позицию и при касании, так что от него «Нет» тоже убегает.
  - Убегание: 12 направлений, выигрывает то, что дальше от пальца, внутри области; после «сколько раз» блок больше не убегает (его можно нажать — RG-01).
  - Следование: экспоненциальное сглаживание с задержкой `lagMs`.
- **BH-03 стираемый слой:** слой — сам блок с любым оформлением. Маска — холст размером с блок (1 пиксель на единицу); кисть стирает режимом `destination-out`. Маска и доля стёртого обновляются раз в 50 мс, доля уходит в движок (TR-14), после порога слой гаснет.
- **BH-04 движение:** угол 0° — вправо, 90° — вниз; разброс и стартовая скорость берутся из зерна. Края считаются по экрану (для вложенного — по родителю): отскок, удаление, «по кругу», остановка. Контур проходится с постоянной скоростью по длине. Скрытый блок не движется, поэтому скрытый образец генератора стоит на месте.
- **BH-05 генератор** работает, пока виден; «Проиграть / Пауза» (AC-06) запускают и останавливают его, «без автозапуска» ждёт «Проиграть». Копии появляются в случайной точке области, с поведениями образца; лимит считает живые копии.
- **BH-06 колесо:** сектор выбирает `RandomSource` движка (в плеере — сервер, RN-01), секторы идут по часовой стрелке от верха в порядке списка. Поворот: не меньше трёх оборотов с замедлением, до середины выпавшего сектора под верхним указателем. В конце — эффект `wheel`, сектор становится «выбран» (CN-03), срабатывает «анимация закончилась» (TR-13). Крутит нажатие, Enter или «Проиграть».
- **BH-07 переворот** — `rotateY` 0° ↔ 180°. После ребра (90°…270°) видна обратная сторона: она заранее отражена, поэтому не зеркальная. Невидимая сторона скрыта и для скринридера. «По действию» — «Проиграть» (AC-06).
- **Производительность (SC-05)** — в три шага:
  1. Движок заменяет `anim`/`overrides` новыми объектами только при изменении, а `BlockView` кеширует стиль и CSS по ссылкам.
  2. Место из документа остаётся в `left/top`, сдвиг — свойство `translate` (без пересчёта раскладки), у движущихся блоков свой слой.
  3. Если кадр только двигает блоки, `RuntimeStore` сдвигает их элементы сам, и React экран не перерисовывает.

  Итог для 50 движущихся блоков с отскоком при CPU ×4 в песочнице без видеокарты: 39 → 45 → 52 → 58–60 кадров/с.

### ADR-028 · 2026-10-22 · Замер кадров SC-05 и доработки P1.9c
- **Где мерить.** SC-05 требует ≥ 50 к/с «на среднем телефоне (эмуляция CPU ×4)». Тест вынесен в `e2e/perf/behaviors-perf.spec.ts` и идёт в проекте `perf-390` (профиль телефона). Этот проект запускается после всех остальных тестов (`dependencies`), по одному тесту. Раньше замер шёл параллельно с соседними тестами и делил с ними процессор: на одной и той же сборке получалось от 41 до 59 к/с. Порог 50 к/с и замедление ×4 не изменились. Измерение стало точнее:
  - сначала 1 с прогрева под замедлением;
  - затем счёт кадров 3 с вместо 2.
- **Ширина 1440 в замер не входит.** Это настольный компьютер, а требование сформулировано для телефона. Без видеокарты стоимость кадра на большой ширине определяет программная композиция в браузере, а не наш код. На 1440 у нас 44–48 к/с. Основной поток при этом занят ~1,7 мс на кадр без замедления; страница из 50 голых `div` даёт те же цифры по стилю.
- **Откат обходов из a499fdd.** В нём быстрый путь `movedOnly` менял уже опубликованные объекты вида на месте. А блоки без зарегистрированного приёмника места просто не двигались. Возвращён вариант ADR-026, с одной поправкой: «только сдвиг» засчитывается, лишь если координаты правда изменились. Иначе изменился ответ или переменная, и экран перерисовывается. Без этой поправки перестал отмечаться выбор в шкале (B-15), тест `render-gallery` ловил это. Сохранена правка из a499fdd: ограничения оси и границ применяются и при отпускании (`dragEnd`).
- **Нет ухода со страницы свайпом.** Плеер ставит `html, body { overscroll-behavior-x: none }`. Иначе горизонтальный жест мимо блока браузер принимает за «назад»: участник тянет подарок или стирает слой — и покидает сборку. Так и падал BH-03 на телефоне: слой исчезал после 60 %, а следующий проход пальцем уводил страницу.
- В CI Playwright дополнительно пишет упавшие тесты аннотациями (`github`-репортёр), чтобы причину было видно без скачивания отчёта.
- **Мышь не выделяет текст** на стираемом и перетаскиваемом блоке (`user-select: none`, отмена `dragstart`). Иначе первый проход мышью выделял надпись слоя, а следующий браузер принимал за перетаскивание выделения и обрывал жест (`pointercancel`): 4 из 6 проходов терялись. Это выяснилось по самоотчёту теста BH-03 в CI.
- **Маска стираемого слоя** — на рисунке внутри блока (`.bk-scratch`), а не на самом блоке: блок ловит палец по всей площади, в том числе над уже стёртым местом.
- **`data-live` у экрана плеера** — экран ожил (обработчики навешаны, движок тикает). Разметку присылает сервер, и e2e ждут этот признак перед жестами.

### ADR-029 · 2026-10-22 · Визуальные регрессии (P1.10)
- **Что проверяется.** `e2e/visual.spec.ts`: галереи P1.4–P1.9 (`/dev/artboard`, `matrix`, `shapes`, `animations`, `render-gallery`, `behaviors`):
  - светлая и тёмная тема, ширины 390 и 1440 — 24 снимка во всю страницу;
  - сравнение через `toHaveScreenshot`, порог `maxDiffPixelRatio: 0.001` (0,1 %);
  - эталоны лежат в `e2e/__visual__`.
- **Повторяемость.** Галереи живые, поэтому снимок делается в одинаковый момент:
  - часы страницы (`page.clock`) стоят, пока страница грузится, потом идут ровно 3 с и останавливаются;
  - `Math.random` подменён генератором с постоянным зерном (частицы, разброс, колесо);
  - CSS-анимации выключены;
  - видео и GIF браузер проигрывает сам, мимо часов, поэтому они закрыты маской.
  - Проверено двумя прогонами подряд: совпадение до пикселя.
- **Где снимаются эталоны.** Только на CI, тем же раннером и браузером, что задание E2E в `ci.yml`: на другой машине шрифты сглаживаются иначе, и любое сравнение падало бы. Порядок обновления эталонов:
  - пушится ветка `visual-baselines/<что меняется>`;
  - workflow `visual-baselines.yml` снимает эталоны, проверяет их повторным прогоном и коммитит обратно в эту ветку;
  - изображения смотрятся в коммите, ветка вливается.
- **Вне CI** сравнение пропускается (`ignoreSnapshots`), если не задан `VISUAL=1`. Локальный браузер другой — без этого тест падал бы у каждого разработчика.
