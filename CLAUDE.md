# «Блокум» — правила для ИИ-агента

«Блокум» (blokum.ru) — конструктор интерактивных сборок: создатель собирает экраны из универсальных блоков (тексты, фото, видео, GIF, фигуры, кнопки, вопросы, контейнеры, зоны), где **любой блок редактируется в любом свойстве**, оживляет их сценариями «Когда → Если → Сделать» и поведениями (так пользователи сами придумывают мини-игры), оформляет **своими** темами, публикует ссылку/QR; участники проходят **без регистрации**, создатель видит результаты в кабинете. Репозиторий называется `sborka` (рабочее имя). Монорепо pnpm + Turborepo: `apps/web` (Next.js), `apps/api` (NestJS), `apps/worker` (BullMQ), `packages/*`.

## Начало сессии
1. Прочитай `docs/PROGRESS.md`. Возьми задачу 🟨 (в работе); если её нет — первую ⬜, у которой выполнены предыдущие задачи фазы.
2. Прочитай задачу в `docs/03-PLAN.md` и **каждое** требование из её «Покрывает» в исходных документах.
3. Поставь 🟨 в PROGRESS и начинай. План работы владельцу на одобрение не отправляй — делай.

## Цикл задачи
реализация → тесты (имя теста начинается с ID требования) → `pnpm verify` → для интерфейса скриншоты 390/1440 (редактор + 1024) и **просмотр их инструментом Read** → коммит `тип(Pn.m): …` → push → CI зелёный (`gh run list -R Olegbolya/sborka --limit 3`) → строки в `TRACEABILITY.md` → ✅ в PROGRESS с хэшем и доказательством → **следующая задача**.

## Жёсткие правила (нарушение = задача не выполнена)
1. **Никаких заглушек.** Запрещены `TODO`, `FIXME`, «not implemented», «упрощённая/базовая версия», «можно доработать позже», фиктивные данные вместо реальной логики, тексты-«рыба». Проверяет `scripts/check-forbidden.mjs`.
2. **Не сокращай объём.** Задача делается так, как написана, со всеми ID из «Покрывает». Если требование невыполнимо как написано — статус ⛔ с причиной и вариантами, а не тихое упрощение. Если задача не влезает в сессию — разбей её на подпункты в PROGRESS («Заметки»), каждый подпункт делай целиком, `main` всегда зелёный, статус остаётся 🟨.
3. **Не ослабляй проверки.** Нельзя удалять/пропускать тесты, снижать пороги покрытия, отключать правила ESLint и TypeScript, править `scripts/check-*.mjs`, `scripts/verify.mjs`, `.claude/` и `.github/workflows/ci.yml`, чтобы «прошло». Изменение проверок — только с записью в `DECISIONS.md` и с разрешения владельца.
4. **Только проверенные утверждения.** Не пиши «работает/готово», если не запускал команду, — приводи команду и итог. Не выдумывай API библиотек: смотри документацию или исходники в `node_modules`.
5. **Не останавливайся рано.** После задачи — следующая. Останавливаться можно, только если: фаза закончена (предложи `docs/prompts/REVIEW.md`); все оставшиеся задачи ⛔ ждут владельца; контекст заканчивается — тогда сначала запиши в PROGRESS точное место остановки.
6. **Не спрашивай лишнего.** Технические решения принимай сам и записывай в `DECISIONS.md`. Владельцу — только вопросы из `00-OWNER-DECISIONS.md` (деньги, статус, домены, доступы, юрист) — в блок «Вопросы владельцу» PROGRESS и в итоговое сообщение.
7. **Итог сессии — строго по шаблону:**
   ```
   Сделано: <задача> — <коммит> — <доказательство>
   Не сделано / частично: <что и почему>   ← обязательно, даже если «нет»
   Нужно от владельца: <или «ничего»>
   Следующий шаг: <задача>
   ```

## Продукт: обязательные принципы
- **Инструменты, а не готовые решения.** Нет «зашитых» игр, тем и шаблонов: интерактив — только через сценарии и поведения `packages/engine/runtime`, оформление — через темы-данные. Если эталонную игру RG-xx нельзя собрать штатно — дорабатывай движок/редактор, а не добавляй частный случай.
- Каждое свойство §5 спецификации работает на каждом типе блока (S-00).
- Продукт полностью работает при **пустых** системных темах, шаблонах и библиотеке. Библиотеку наполняет владелец — не загружай туда ничего.
- Один рендер: вид блоков — только в `packages/renderer`; логика прохождения — только в `packages/engine`. Не дублируй.
- Всё, что видит пользователь, — **на русском** (включая ошибки и письма). Английские слова в интерфейсе запрещены.
- Ограничения тарифов — только через `Entitlements` на сервере.
- Ключ правильных ответов, баллы и теги результатов **никогда** не уходят в браузер участника.
- Нет полей пароля, нет приёма платежей от участников, нет пользовательских HTML/JS/SVG (из SVG — только контур), Lottie только через `dotlottie-web`, шрифты только перекодированные, ссылки из сценариев — только по жесту участника, нет отпечатков браузера.
- Только российские внешние сервисы (`02-ARCHITECTURE.md` §1). Google, Cloudflare, Resend, Stripe, Sentry, иностранные CDN и шрифты запрещены (`scripts/check-foreign-services.mjs`).
- Ассеты (шрифты, стикеры, звуки, мемы-реакции) — только с лицензией в `packages/themes/assets/LICENSES.json`; чужие мемы и картинки из интернета не скачивать.

## Сервер (общий с BST!)
- Домашний сервер `95.105.7.135`, пользователь `deploy`. Прямого доступа из облачной сессии нет — только через `deploy.yml` и `server-diagnostics.yml` (`gh workflow run server-diagnostics.yml -R Olegbolya/sborka`).
- Блокум: `~/blokum`, порты 3100 (api) / 3110 (web), PM2 `blokum-*`, база `blokum_db`, Redis БД 3 (префикс `bk:`), nginx `blokum.conf`, домен `blokum.ru`.
- **Запрещено:** трогать `~/bst`, его nginx-конфиг, базу, Redis-БД, процессы; `pm2 restart all|delete all|kill`; перезапускать PostgreSQL/Redis/nginx без `nginx -t`.
- Секреты не печатать и не коммитить; `.env.prod` живёт только на сервере.
